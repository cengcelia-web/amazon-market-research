# 产品设计说明

## 目标与用户任务

帮助跨境电商产品/运营人员按统一口径完成类目研究，并将证据转化为产品配置、推广与利润方案。项目是以Skill为载体的AI工作流原型，八阶段流程由用户提供，AI辅助整理成可执行指令与参考规范。

## 需求到设计的对应

| 业务问题 | 设计决策 | 可检查的行为 |
| --- | --- | --- |
| 一次性生成报告容易忽略数据缺口 | 阶段确认与输入门槛 | 缺市场报告时先列缺项，不继续生成增长结论 |
| 商品卖点难横向比较 | 标签字典与全量逐行处理 | 每个输入商品有输出记录，标签有证据，缺失值单列 |
| 数据口径混用导致结论失真 | 来源、周期、分母和指标定义要求 | 流量得分不被写成曝光，FBA不被写成AMZ自营 |
| 推广策略脱离利润 | CPA/CPC/ACOS关联规范 | 预算建议标注假设，成本不齐时不输出真实盈利判断 |
| 汇报无法追溯 | 观察、推断、假设分别标注 | 机会点附证据、替代解释及验证动作 |

## 交互状态设计

进入阶段 → 检查输入 → 缺失时等待补充 → 分析与交付 → 等待下一阶段确认。

状态记录包含站点、类目、周期、当前阶段、授权范围、输入、输出、待补数据。上述状态由AI按文档维护，目前没有独立状态机程序或持久化服务；用户仍需检查AI是否正确执行。

## MVP范围

已交付：八阶段规则、两份专项分析参考、技能展示信息、使用示例、行为验收案例、发布包静态校验工具。

尚未交付：真实类目完整报告、自动爬虫、实时数据接口、自动广告投放、模型训练、用户使用效果验证。
## 验收设计

验收使用 [evaluation.md](evaluation.md) 的输入场景进行真实对话测试。记录使用的模型、日期、工具权限、输入数据、完整输出以及人工评判；不能以“指令中写了要求”替代“行为已满足要求”。

真实数据试点可测量：阶段跳转合规情况、缺失识别情况、商品标签人工复核准确率、关键结论证据覆盖率、人工返工次数和完成耗时。先建立基线再比较，不预设提升比例。
